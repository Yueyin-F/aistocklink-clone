# "股票资讯AI智能分析"网站复现技术报告

作者：范广乐　　日期：2026 年 8 月

## 一、任务背景

推免考核中布置了一个复现任务，对象是 www.aistocklink.cn 这个网站。打开之后它会跳到 gupiao.yaozhineng.com，是一个叫"股票资讯AI智能分析"的金融资讯类网站，主要功能包括财经新闻聚合、个股行情与AI分析、股票评分、板块龙头追踪、事件传导分析等。

任务的要求是把它复现出来。我的理解是两层：一是页面和功能要尽量还原，二是要能跑起来、有真实数据，而不是做个样子。另外我也希望在这个过程中尽量自己动手，把涉及的工程问题都过一遍，这样如果老师问起来，我能讲清楚每一块是怎么做的。

## 二、复现对象分析

拿到任务后我首先不是急着写代码，而是先把这个网站"拆开"看。

它是典型的单页应用：首页只有一段 HTML 框架，真正的页面内容全靠 JavaScript 渲染。通过浏览器开发者工具看它加载的资源，能确认它用的是 Vue 3 和 Element Plus 组件库，图标和图表用到了 ECharts。页面脚本是按路由拆成一个个小文件按需加载的（Webpack 的代码分割），也就是说很多页面代码不在主包里，要等用户访问那个页面才会下载。

我做的第一件事是把这些脚本文件都抓下来，然后从里面整理出三样东西：

- 路由表。整个网站有 20 个页面，包括首页、股票搜索、股票详情、业绩预测、十倍股评分、趋势股评分、事件传导、板块龙头、下载页等，每个页面对应一个路由，页面标题也都写在里面。
- 组件结构。比如首页并不是一整块代码，而是由八个子组件拼出来的：资讯轮播、指数概览、风口龙头面板、机构调研推荐热门股、自选股卡片、盈利预测榜等。我照着这个结构来组织我的页面代码。
- 接口调用。页面里所有数据请求的后端地址、参数、返回格式，都可以从脚本里看出来。它的后端是另一个独立服务（gupiao-api.yaozhineng.com），数据来源包括腾讯财经、财联社、Tushare、PostgreSQL，还有一个叫 Kronos 的时序预测模型，用来做股价预测。

这步做扎实了，后面写代码基本就是按图索骥。

## 三、整体方案

- 前端：Vue 3 + Vue Router + Pinia + Element Plus + ECharts，Axios 发请求
- 数据：通过本地代理转发到原站的公开接口，保证页面展示真实数据
- 构建：自己基于 @vue/compiler-sfc 写了一个单文件组件编译插件，配合 Rollup 打包
- 测试：用 jsdom 搭了一套无浏览器的自动化渲染测试
- 部署：最终部署在 Netlify 上，得到一个公网地址

架构上，浏览器访问的是静态页面，页面里的 /api 请求由托管平台转发到原站后端，中间不需要我维护服务器。这样部署成本低，也比较稳定。

## 四、主要实现过程

### 1. 前端工程

项目用 Vite 起步，但后来遇到一个环境限制：我的开发环境里没法运行需要子进程的工具（esbuild、浏览器自动化这类都不行），Vite 和它的压缩器都跑不起来。所以我干脆绕开它，自己写了一个 Vue 单文件组件的编译插件：用 Vue 官方的 @vue/compiler-sfc 把 .vue 文件拆成脚本、模板、样式三部分分别编译，再把编译产物交给 Rollup 打包，压缩用 Terser。虽然绕了一段路，但这也让我把 Vue 单文件组件从源码到运行时的整个编译链路亲手走了一遍，算是因祸得福。

### 2. 页面实现

按照整理出来的路由表，原站的 20 个页面我全部做了出来，另外还自己加了一个对比页。这里列几个重点的：

- 首页。包含资讯轮播（头条、国内、外围三组新闻，自动轮播、可以手滑切换）、指数行情卡片、风口龙头面板、机构调研推荐热门股、我的自选股、盈利预测更新榜（分页）。风口龙头这块原站做得比较重：左边是一张风口概念的气泡图，点击气泡能打开详情，里面有板块的涨幅、成交额、AI 对传递方向和风险的解读，还有一张上游/下游产业链的传导图，以及精选股、上游带动、下游传导三张股票列表。这些我都照着做了。
- 个股详情。顶部是行情卡（价格、涨跌、开高低、量能、估值这些），下面是几个标签页：K线图、AI分析、个股新闻、资金流向、财务与业绩预测、历史评价。AI分析这一块展示的是接口返回的结论、核心逻辑和风险提示，我写了一个轻量的 Markdown 渲染组件来显示里面的格式。
- 事件传导。这是比较有特点的一个页面，列表里的每条事件都带了 AI 生成的传导分析，比如某个板块利好会传导到哪些行业、强度多大。详情页还有关键点、机会、风险提示、传导链表格、历史类似事件这些内容。
- 板块龙头。按 BK 开头的板块代码查询龙头股，支持短线、中线、长线周期切换，按主力净流入排名。

### 3. 数据接入与降级

所有接口都封装在一个 API 模块里，页面只跟这个模块打交道。接口返回的字段是中文名（比如"股票代码""涨跌幅"），我就按原站的实际返回去适配。

有个现实问题是原站部分接口不太稳定，最典型的是K线接口，经常超时。我的处理方式是：接口正常就用真实数据；超时或失败时，生成一组可复现的模拟数据顶上（种子取股票代码，同样的代码每次生成的结果一致），页面不会白屏，也不会因为随机数导致每次刷新数据都变。新闻、行情这些接口偶尔也会失败，这类就保留上一次的成功数据继续展示。

## 五、自己额外加的几个功能

复现之外我加了几样原站没有的东西，初衷是想说明我不只是照抄：

- 深色/浅色主题切换。导航栏上有个开关，切换后全站包括表格、弹窗、图表都会跟着变，选择会记住，下次打开还在。原站没有这个功能。
- 本地缓存层。把风口龙头、盈利预测榜这类数据缓存到浏览器本地，再次打开页面秒出，后台再静默刷新；断网的时候也能看到上次的数据。页面上会标注当前是缓存数据。
- K线上的AI价格预测。原站后端接了一个叫 Kronos 的时序模型，我把它用了起来：在K线图上叠加未来五个交易日的预测，用虚线画均值路径、用半透明区域画置信区间，图上方显示方向概率（偏多还是偏空）和置信度。
- 个股对比页。可以添加最多六只股票，对比十二项行情指标，指标最优的格子会高亮，下面还有一张六十个交易日的归一化走势对比图，方便直观看出谁强谁弱。

## 六、测试与验证

我自己写了一套基于 jsdom 的自动化测试：把整个应用打进一个文件，在 jsdom 模拟的浏览器环境里挂载，然后逐个访问 15 个主要页面，检查每个页面是否渲染出了关键内容，同时收集页面运行时的 JavaScript 报错。目前结果是全部通过、零报错。

部署到公网之后，我又把同一套测试指向线上地址跑了一遍，确认经过网络、HTTPS、代理这些环节之后，页面和数据依然是正常的。

## 七、部署上线

部署选的是 Netlify，原因很简单：免费、自带 HTTPS、不用维护服务器。项目推到 GitHub 后，Netlify 自动完成构建和发布。数据代理是通过它的重写规则把 /api 请求转发到原站后端，和本地开发时的行为保持一致。

最终地址：https://spectacular-naiad-a86bcb.netlify.app

## 八、遇到的问题与解决

- 开发环境限制。如上所说，子进程类工具全不可用，为此自己实现了 SFC 编译插件和纯 JavaScript 的构建链路。
- 原站改版。复现过程中原站重新部署过一次，脚本文件名全变了，说明它还在迭代。我以最新的线上版本为准重新做了分析。
- 接口不稳定。K线、半年报、板块数据源（Tushare）都有过超时或返回空的情况，统一做了降级。
- 部署地址稳定性。一开始尝试了几种免费的临时隧道方案（serveo、localhost.run 之类），都不太稳定，会限流或者自动断开，所以最终选了 Netlify 这种正式托管，拿到一个长期可用的地址。
- 登录态。原站登录、自选股依赖它的账号体系，跨域环境里没法完整打通，这部分做了提示和降级处理。

## 九、不足与后续打算

- 自选股、推送设置这类依赖登录的功能在线上环境不能完整使用，如果后续有服务器，可以按仓库里的部署文档搭一套完整的（宝塔或 Docker 方案）。
- 事件传导、AI 分析这类内容的生成逻辑在原站后端，我只能调用它返回的结果，没法复现模型本身。如果时间允许，后续可以考虑用大模型自己实现一套类似的分析。
- K线数据目前依赖原站接口，接口一超时就只能展示模拟数据，可以换成其他稳定的行情数据源。

总的来说，这次任务让我把从前端框架、组件化、构建打包到自动化测试、部署上线这一整条链路完整地走了一遍，也踩了不少坑、填了不少坑。代码和文档都在 github.com/Yueyin-F/aistocklink-clone，欢迎老师审阅指正。

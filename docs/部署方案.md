# AI StockLink 复现项目 · 上线部署方案（全路线）

> 目标：把项目部署上线，交付**网址**（而非压缩包）。
> 本文档提供 **7 套部署方案**，从"国内服务器+宝塔"到"完全免服务器"，按需选择。
> 推荐优先级：**A（完整功能）> B（Docker 一键）> E（零成本演示）> F（免费托管）**。

## 方案 A：宝塔面板（推荐 · 完整教程见原版）

**步骤速览**
1. 买服务器（2核2G，CentOS/Ubuntu/Debian），安装宝塔：`wget -O install.sh https://download.bt.cn/install/install_6.0.sh && bash install.sh`
2. 宝塔软件商店装：Nginx 1.24+、Node.js 20 LTS、PM2
3. 上传项目到 `/www/wwwroot/aistocklink`，终端执行：
   ```bash
   cd /www/wwwroot/aistocklink
   npm install --registry=https://registry.npmmirror.com
   npm run build:rollup
   pm2 start serve.mjs --name aistocklink
   pm2 save && pm2 startup
   ```
4. 宝塔添加站点（根目录指向 `dist`，纯静态），按 `deploy/nginx.conf.example` 配置 `/api`、`/kronos` 反向代理与 SPA 回退
5. 域名解析 A 记录 → 服务器 IP；宝塔 SSL → Let's Encrypt 一键 HTTPS；防火墙仅放行 80/443

**配套文件**：`deploy/nginx.conf.example`、`ecosystem.config.cjs`

## 方案 B：Docker Compose 一键部署（Caddy 自动 HTTPS）

无需手动配 Nginx 证书，**Caddy 自动申请/续期 Let's Encrypt**。
**推荐用一键脚本**（自动装 Docker、构建、启动、自检、输出网址）：

```bash
# 有域名（需先把 A 记录解析到服务器 IP）：
bash deploy/install-docker.sh aistock.你的域名.com

# 暂无域名（先用服务器 IP 直连，稍后可补域名开 HTTPS）：
bash deploy/install-docker.sh
```

手动步骤（等价）：

1. 服务器装 Docker：`curl -fsSL https://get.docker.com | bash`
2. 上传项目，修改 `deploy/Caddyfile` 与 `deploy/docker-compose.yml` 中的域名
3. 域名 A 记录 → 服务器 IP
4. 一键启动：
   ```bash
   cd aistocklink
   docker compose up -d --build
   ```
5. 访问 `https://你的域名`（Caddy 自动发证）

**配套文件**：`Dockerfile`、`deploy/docker-compose.yml`、`deploy/Caddyfile`、`deploy/install-docker.sh`

## 方案 C：1Panel 开源面板

宝塔的现代化替代（开源、Docker 原生、无强制绑定）。

1. 安装：`curl -sSL https://resource.fit2cloud.com/1panel/package/quick_start.sh -o quick_start.sh && bash quick_start.sh`
2. 面板内：应用商店安装 OpenResty（Nginx 系）+ Node.js；网站 → 创建网站 → 静态站指向 `dist`
3. 应用商店安装「PM2 管理器」或直接 `docker run -d -p 4173:4173 aistocklink`（方案 B 的镜像）
4. Nginx 反向代理配置与方案 A 相同（参考 `deploy/nginx.conf.example`）

## 方案 D：systemd 极简部署（无面板、无 PM2）

适合熟悉命令行的同学，不安装任何额外管理软件。

1. 上传项目到 `/opt/aistocklink`，构建：
   ```bash
   cd /opt/aistocklink
   npm install --registry=https://registry.npmmirror.com
   npm run build:rollup
   ```
2. 安装服务单元：
   ```bash
   cp deploy/systemd/aistocklink.service /etc/systemd/system/
   systemctl daemon-reload
   systemctl enable --now aistocklink
   systemctl status aistocklink   # 确认 active (running)
   ```
3. 安装 Nginx 并配置反代（同方案 A 第 4 步）或直接使用 Caddy 单二进制：
   ```bash
   apt install caddy    # 或下载官方单文件二进制
   # 用 deploy/Caddyfile（把 app:4173 改为 127.0.0.1:4173）
   caddy run --config deploy/Caddyfile
   ```

**配套文件**：`deploy/systemd/aistocklink.service`、`deploy/Caddyfile`

## 方案 E：内网穿透 · 免服务器出网址（零成本演示）

**适用**：面试/验收前快速交付可访问网址；本地电脑即可，不买服务器、不备案。
**已实测**：本项目在 Windows 环境用 **E-2 serveo** 成功出网（见下方记录）。

### E-1 Cloudflare Tunnel（推荐，免费、稳定、支持自定义域名）
```bash
# 1) 安装 cloudflared（Windows 下载 exe / Linux 一条命令）
# Windows: 下载 https://github.com/cloudflare/cloudflared/releases 的 exe
# Linux:   curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o cloudflared && chmod +x cloudflared

# 2) 本地先启动服务
node serve.mjs 4173

# 3) 建立隧道（免费得到 https://xxx.trycloudflare.com 临时网址）
cloudflared tunnel --url http://127.0.0.1:4173
```
- 立即获得公网 https 网址，无需服务器/备案；
- 想用自己域名：Cloudflare 面板 → Zero Trust → Tunnels → 绑定域名（免费 DNS）。

### E-2 serveo（无需安装，Windows/macOS/Linux 自带 SSH 即可用）✅ 已实测
```bash
# 1) 本地启动服务
node serve.mjs 4173

# 2) 一键建立反向隧道（Windows 自带 OpenSSH；无需账号、无需下载软件）
ssh -o StrictHostKeyChecking=no -R 80:localhost:4173 serveo.net

# 3) 终端会打印公网网址（形如 https://xxxxxx.serveousercontent.com），直接发给对方
```
实测记录（本项目）：
- 输出 `Forwarding HTTP traffic from https://xxxx.serveousercontent.com` 即为成功；
- 公网访问首页、个股详情、业绩预测、事件传导、个股对比均正常，**0 JS 错误**；
- 免费隧道为大文件传输有限制：需配合本项目已启用的 **Terser 压缩构建 + 服务端 gzip**（app.js 2.6MB → 网络传输仅约 340KB），已全部验证可稳定传输；
- **自动重连脚本**：项目根目录提供 `start-tunnel.ps1`（右键用 PowerShell 运行），隧道断线自动重连并实时打印最新网址，避免手动反复执行；
- **已知局限（实测）**：
  - serveo 免费版在连续使用后会被限流（访问返回 502），重启隧道可恢复，子域名会变化；
  - localhost.run 免费隧道约 10~20 分钟无流量会被服务端断开（`tunnel inactivity timeout`）；
  - 原站 API 未开启 CORS（`Access-Control-Allow-Origin` 为空），因此纯静态托管无法由浏览器直连数据，必须走代理（方案 F 的 URL 重写 / Worker 或本方案的 Node 代理）；
- 结论：免费隧道适合**短期演示**；**正式交付请用方案 A/B 部署自有服务器获取稳定域名**。

### E-3 cpolar / frp（国内速度更优）
- **cpolar**（国内团队、免费额度、支持自定义二级域名）：
  ```bash
  cpolar authtoken <你的token>
  cpolar http 4173
  ```
- **frp**（自建中转，需要一台有公网 IP 的轻量服务器，适合长期稳定）：
  ```bash
  # 服务端 frps.ini
  [common] bind_port = 7000
  # 客户端 frpc.ini
  [common] server_addr = 你的服务器IP  server_port = 7000
  [web] type = http  local_port = 4173  custom_domains = aistock.你的域名.com
  ```

## 方案 F：免费静态托管（Vercel / Netlify / Cloudflare Pages）

无需服务器，**全球 CDN + 自动 HTTPS + Git 推送即发布**。原理：前端静态部署 + URL 重写把 `/api`、`/kronos` 代理到真实数据源。

### F-1 Vercel（推荐，国内可访问性好）✅ 已备好

**前置（已完成）**：项目根目录已放好 `vercel.json`（代理 `/api`、`/kronos` + SPA 回退）、`.gitignore`，本地 git 仓库已初始化并提交，构建命令已验证可用。

**操作步骤（共 3 步，约 10 分钟）**

1. **推送到 GitHub**
   - github.com → 注册/登录 → New repository → 名称 `aistocklink-clone` → Public → Create；
   - 本机命令行执行（把用户名替换成你的）：
     ```bash
     cd C:\Users\28129\Desktop\项目\aistocklink-clone
     git remote add origin https://github.com/<你的用户名>/aistocklink-clone.git
     git push -u origin main
     ```
2. **Vercel 导入**
   - vercel.com → 用 GitHub 账号注册（免费 Hobby 版）→ New Project → Import 该仓库；
   - 按下面配置（关键）：
     | 配置项 | 值 |
     |---|---|
     | Framework Preset | **Other** |
     | Build Command | `npm run build:rollup` |
     | Output Directory | `dist` |
     | Install Command | `npm install`（默认即可） |
   - 点 Deploy，约 1~2 分钟完成。
3. **验收**
   - 得到 `https://aistocklink-clone-xxxx.vercel.app`，浏览器打开；
   - 检查：首页指数/新闻/风口龙头有真实数据；打开 `https://...vercel.app/stock/600519` 深链接不 404（SPA 回退生效）；
   - 可绑定自定义域名（Settings → Domains）。

**已知限制（免费托管）**：登录/自选股依赖原站 Cookie，在 Vercel 上可能不可用（页面自动降级为缓存/空态 + 提示），UI 与数据展示不受影响；若 `/api` 代理出现 502，可把 `vercel.json` 中代理目标替换为其他中转（联系开发者协助）。

### F-2 Netlify
- 根目录提供 `deploy/netlify.toml`（复制为根目录 `netlify.toml`）：`build_command = "npm run build:rollup"`、`publish = "dist"`，含 `/api`、`/kronos` 外部 200 代理与 SPA 回退；
- 或直接拖拽 `dist/` 文件夹到 Netlify Drop 即上线。

### F-3 Cloudflare Pages + Worker 代理
1. Pages 部署 `dist/`（拖拽或 Git 接入），得到 `https://xxx.pages.dev`；
2. 创建 Worker（粘贴 `deploy/cloudflare-worker.js`），绑定自定义域名 `api.你的域名.com`；
3. 前端把 `src/api/index.js` 的 `baseURL` 改为 `https://api.你的域名.com/api` 后重新构建发布。

> ⚠️ 纯静态托管走 URL 重写代理：数据可正常展示；登录/自选股依赖原站 Cookie 的场景可能受限（同源策略），此时页面会优雅降级（缓存/空态 + 提示），UI 演示不受影响。

**配套文件**：`deploy/vercel.json`、`deploy/netlify.toml`、`deploy/cloudflare-worker.js`

## 方案 G：国外 PaaS（Render / Railway / Fly.io）

免运维、Git 推送即部署、自带 HTTPS，适合有 GitHub 的同学（免费额度内）。

| 平台 | 免费额度 | 说明 |
|---|---|---|
| **Render** | 免费 Web Service（闲置 15 分钟休眠） | `Build Command: npm run build:rollup && npm install`，`Start Command: node serve.mjs 4173`；绑定域名自动 HTTPS |
| **Railway** | 试用额度（$5/月约 500 小时） | 同样以 Node 启动命令运行 |
| **Fly.io** | 免费配额（按用量） | 需要 `fly.toml`，Node 容器运行 |

> 注：国外节点国内访问延迟较高，适合演示而非正式使用；登录态依赖原站 Cookie 也可能受限（可接受）。
